# Zasady współpracy

## 1. Fork repozytorium
Każdy członek zespołu tworzy własny fork
głównego repozytorium.

## 2. Tworzenie gałęzi
Każde zadanie realizujemy na osobnej gałęzi.

Przykłady:
- feature/html
- feature/css
- feature/responsive

## 3. Commity
Każda zmiana powinna mieć czytelny commit.

Przykłady:
- Add HTML structure
- Add CSS styles
- Add task functionality

## 4. Pull Request
Po zakończeniu zadania tworzymy Pull Request.

Pull Request musi zawierać:
- Tytuł
- Opis zmian
- Link do zadania w Trello
- Informację o problemach

## 5. Akceptacja zmian
Project Manager sprawdza Pull Request
i scala go z główną gałęzią projektu.
